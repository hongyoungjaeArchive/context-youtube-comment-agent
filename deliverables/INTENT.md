# CONTEXT — 제작 의도

> TRACK 2 · 마케팅 AI 에이전트 · 유튜브 댓글 에이전트 대시보드
> 아래 숫자는 2026-10-21 실제 실행 기록이다. 측정하지 않은 값은 적지 않았다.

## 한 줄 요약

**"그 영상을 본 사람만 쓸 수 있는 댓글"을 AI가 쓰고, 사람이 버튼 한 번으로 게시한다.** 맥락은 AI가 이해하고, 게시 범위와 횟수는 코드가 지킨다.

## 1. 왜 자막부터 읽게 했나 — 맥락 이해

같은 연애 고민 영상이라도, 제목만 보고 쓴 댓글은 어느 영상에 달아도 말이 됩니다. 평가 기준의 "그 영상에서만 나올 수 있는 댓글"을 만들려면 영상이 **실제로 한 말**이 필요했습니다.

- 공개 영상의 한국어 자막을 45초 단위 구간과 타임스탬프로 나눠 근거로 저장합니다. 자막이 없으면 제목·설명을 씁니다.
- AI는 그 근거 안의 말만 인용할 수 있습니다. 인용한 말이 근거 원문과 다르면 코드가 차단합니다(`QUOTE_MATCH`).
- 화면에는 "자막 발언 반영 (3:04)"처럼 어느 장면을 짚었는지 함께 보여 줍니다.
- 실측 결과: 지정 5개 채널에서 영상을 하나씩 골랐습니다. 5개 모두 자막을 확보했고(12~40구간), 만든 초안 15개가 모두 자막 속 말을 짚었습니다. 영상끼리 같은 문장은 없었습니다.

## 2. 왜 이런 말투인가 — 운명원 유도

광고처럼 읽히는 순간 사람들은 그냥 지나칩니다. 그래서 과제 예시 댓글의 구조를 그대로 따랐습니다.

> 영상 속 한 마디에 대한 반응 → 내 연애 고민 한 마디 → "인연·타이밍은 정해진 게 있나" → 운명원 연애사주를 **"보고 싶다"**

- 운명원은 "아직 안 본 사람의 바람"으로만 언급합니다.
- 다음 표현은 규칙으로 막습니다: "봤는데 맞더라" 같은 지어낸 후기, "유명한·1위·적중률" 같은 평판 주장, 링크, 해시태그.
- 처음 쓴 버전은 "운명원은 연애운을 볼 수 있는 곳이래요"처럼 안내문 같았습니다. 9개 중 1개만 품질 기준을 넘었습니다.
- 프롬프트를 고친 뒤(B-2.0) 15개 중 10개가 기준을 넘었습니다(Claude 품질 심사 70점 이상, 규칙 위반 0).

## 3. 왜 "AI가 쓰고 사람이 누르는" 구조인가 — 운영 규칙

게시는 되돌릴 수 없는 행동이라서, AI 판단에 맡기지 않고 코드와 사람이 결정하게 했습니다.

- **허용 범위**: 지정 5개 채널의 Channel ID 허용 목록과 본인 테스트 영상만 대상입니다. 직접 입력한 링크도 YouTube API로 채널을 확인한 뒤 막습니다.
- **영상당 1개·하루 10개**: 화면이 아니라 서버와 DB(UNIQUE 제약, 조건부 증가)에서 강제합니다. 동시에 두 번 눌러도 하나만 통과합니다.
- **기록**: 어느 영상에, 어느 프로필로, 무슨 댓글을, 성공했는지 실패했는지를 시간순으로 남깁니다. 실패하면 이유와 화면 캡처도 남깁니다.
- **애매하면 멈춤**: 게시 버튼을 누른 뒤 결과를 확인하지 못하면 `UNKNOWN`으로 보류하고 자동으로 다시 게시하지 않습니다. 중복 댓글이 스팸보다 더 나쁘다고 봤습니다.
- **승인 결속**: 승인한 뒤 문장을 한 글자라도 고치면 승인이 자동으로 풀립니다.

## 4. 왜 화면을 이렇게 줄였나 — 사용성

처음 보는 사람은 세 번만 누르면 됩니다: **[영상 불러오기] → 영상 클릭 → [댓글 달기]**.

- 영상을 고르면 분석이 자동으로 시작되고, 고민 한 줄과 추천 초안 1개가 바로 보입니다.
- 다른 초안, 직접 고치기, AI가 읽은 근거, 품질 평가 실험실(Evaluation Lab)은 접어 두었습니다. 필요한 사람만 펼쳐 봅니다.

## 5. 실제 게시 방식

- 평소 쓰는 Chrome이 아니라 **전용 프로필 폴더**로 Chrome을 엽니다(Playwright `launchPersistentContext`).
- 로그인은 사람이 직접 합니다. 앱은 비밀번호를 다루지 않습니다.
- 댓글창을 열고 한 글자씩 입력합니다. 입력된 문장이 승인한 문장과 같은지 확인한 뒤 게시하고, 댓글 목록에서 내 댓글이 보여야 "게시 완료"로 표시합니다.
- 시연과 실제 게시는 본인 테스트 영상에서만 합니다.

## 6. 가점 기능

| 가점 | 구현 |
|---|---|
| 링크 직접 입력 | 채널 확인 후 허용 범위 밖이면 차단 |
| 새 영상 초안 즉석 생성 | 영상을 고르면 바로 분석·초안 생성 (로컬 Claude Code, 추가 비용 없음) |
| 뜨기 직전 영상 찾기 | '연애' 검색 → 최근 36시간 · 조회수 1,000~5,000 · 시간당 150 이상. 실측 50개 중 19개. 지정 채널 밖이라 **초안까지만**(승인은 서버가 차단) |
| 프로필 1~3개 | 최대 3개 등록, 실행마다 사람이 고름. 계정 자동 순환은 스팸 위험 때문에 일부러 넣지 않음 |

## 7. 검증

- 자동 테스트: 단위·통합 152개, 화면 E2E 13개.
  - 로컬 가짜 YouTube 페이지에서 실제 Chromium으로 입력·게시·확인까지 실행합니다.
  - 장애 주입 10종: 두 프로필 동시 제출, 제출 직후 크래시, 근거 변경, 승인 후 1글자 수정, 하루 11번째 게시, 로그인 만료·CAPTCHA 등.
- 실제 환경 리허설(게시 없이): 한국어 YouTube에서 로그인 판정, 댓글창, 한 글자씩 입력, 입력 문장 일치, 게시 버튼 활성화까지 확인했습니다.
  - 이 과정에서 실제 YouTube에서만 생기는 문제 2건을 찾아 고쳤습니다. 상단 아바타가 늦게 그려져 로그인을 놓치던 문제와, 로그인 창이 열린 채 확인하면 서버 오류가 나던 문제입니다.
- 비밀값: API 키는 macOS Keychain에만 둡니다. 저장소와 로그는 키 형태 문자열 검사(`npm run secret-scan`)에서 0건입니다.
