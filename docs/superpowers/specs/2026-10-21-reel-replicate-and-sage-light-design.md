# 릴스 따라 만들기 스킬 + CONTEXT 밝은 테마·Sage 비서 설계

작성일: 2026-10-21 · 대상: `~/.claude` 개인 스킬/플러그인, `apps/web`·`apps/server`

## 1. 의도 (왜 만드나)

사용자는 인스타 릴스에서 본 UI 디자인·기능을 Claude가 **직접 보고** 자기 프로젝트에 따라 만들게 하고 싶다. 매번 "이 릴스 봐 줘"를 손으로 설명하지 않고, 링크 하나로 "보기 → 명세 → 구현 → 원본 대조 검수"가 같은 품질로 반복되길 원한다.

첫 실전 대상은 릴스 `instagram.com/reel/Det6RW1z-Tv` (code.xr "AI Dashboard", 6.4초)를 CONTEXT 마케팅 콘솔(`http://127.0.0.1:4317`)에 적용하는 것이다. 사용자가 원하는 것: **밝은 색감**, **Sage 구슬 같은 움직임**, 그리고 Sage가 **실제로 질문에 답할 것**.

## 2. 파트 A — 스킬/플러그인 `reel-replicate`

### 목표
- 인스타 릴스(및 유튜브 쇼츠·틱톡 등 영상 링크) URL을 받으면 Claude가 장면을 뽑아 본다.
- 결과물: `reel-spec.md`(장면 타임라인, 디자인 토큰, 레이아웃, 컴포넌트 목록, 움직임 명세, 기능 명세) + 장면 이미지 폴더.
- 대상 프로젝트의 스택을 읽고 그 스택의 관용구로 구현(새 라이브러리는 꼭 필요할 때만).
- 구현 후 같은 장면을 대상 앱에서 스크린샷 → 원본 프레임과 나란히 비교한 검수표 작성.

### 장면 추출 방식 (이번 세션에서 실제로 동작 확인한 방법)
1. **1순위: Chrome(claude-in-chrome)** — 사용자가 로그인된 Chrome에서 릴스를 열고, JS로 `<video>`를 찾아 `pause()` 후 `currentTime`을 일정 간격으로 옮기며 영상 영역만 `zoom` 캡처. 로그인 쿠키 문제·다운로드가 없다. 영상 길이에 따라 간격 자동 결정(≤10초: 0.5초, ≤60초: 1~2초, 그 이상: 장면 변화 위주 최대 40장).
2. **2순위: 기존 `watch` 플러그인(yt-dlp + ffmpeg)** — Chrome이 안 될 때. ffmpeg는 설치돼 있고 yt-dlp는 없음 → 설치는 사용자 승인 후. 인스타 쿠키가 필요하면 사용자에게 안내만 한다(비밀번호 입력은 하지 않음).
3. 캡션 텍스트(설명·해시태그·기술 스택 언급)는 `get_page_text`로 같이 수집해 명세에 "제작자가 밝힌 스택"으로 기록.

### 구성 (파일)
- 위치: `~/.claude/skills/reel-replicate/` (개인 스킬) — 사용자는 "스킬이랑 플러그인"을 원했으므로, 같은 내용을 `/reel` 슬래시 명령으로 부를 수 있게 개인 플러그인 `~/Developer/reel-replicate-plugin/`(commands/reel.md + skills/reel-replicate)로 감싸 설치한다.
- `SKILL.md`: 트리거("이 릴스 따라 만들어", 인스타/쇼츠 링크 + "만들어/넣어"), 4단계 체크리스트, 금지사항.
- `reference/capture.md`: Chrome 프레임 캡처 JS 조각과 간격 규칙, watch 플러그인 대체 경로.
- `reference/spec-template.md`: reel-spec.md 양식.
- `reference/compare.md`: 원본/결과 대조 검수표 양식(장면별 일치/차이/조치).

### 비목표 / 안티골
- 영상 다운로드 파일을 저장소에 커밋하지 않는다(프레임은 스크래치패드 또는 `.reel/` + gitignore).
- 원작자 브랜드명·로고·고유 일러스트를 그대로 베끼지 않는다. 레이아웃·움직임·패턴만 차용하고 이름은 대상 프로젝트 것으로 바꾼다(예: "Codexr" → 프로젝트 사용자명, 건물 사진 → 해당 도메인 데이터).
- "댓글로 Code 달면 소스 줌" 같은 외부 행동은 하지 않는다.

## 3. 파트 B — CONTEXT 밝은 테마 + Sage

### 원본에서 관찰한 것 (장면 기준)
- 0.3s: 흐림(blur) 상태에서 시작, 화면 중앙 상단에 파란 구슬(흰 눈 2개, 글로우).
- 1.3s: 대시보드 등장. 웜그레이 배경(#ECEAE5 근처), 흰 카드 radius ~16px, 아주 옅은 그림자. 왼쪽 알약형 흰 세로 사이드바(아이콘 + 호버 툴팁 "Wallet"), 활성 아이콘은 검은 원. 상단: 인사말 + 부제, 알약형 검색창 "Search or ask Sage…" + 검은 원형 버튼, 원형 아이콘 버튼(알림 뱃지). 강조 카드는 세이지 그린 배경.
- 2.3s: 화면 전환 시 콘텐츠가 사라지고 구슬이 중앙에서 "I'm Sage, your dashboard AI" 말풍선.
- 3.3~5.1s: 새 화면 카드들이 흐림→선명으로 순차 등장(stagger). 숫자 카드, 미니 라인차트, 원형 게이지, 카드 그리드.
- 4.2s~: 오른쪽 아래 검은 알약 버튼 "Ask Sage"(구슬 미니 아이콘).
- 6.0s: 오른쪽 채팅 패널 슬라이드 인, 본문이 왼쪽으로 줄어듦. 패널: 큰 구슬, "Hi …, I'm Sage", 설명, 추천 질문 칩, 하단 입력창.

### B-1. 밝은 테마 (전면 교체)
- `apps/web/src/index.css`의 `@theme` 토큰을 밝은 값으로 교체: bg 웜그레이, surface 흰색, elevated 아주 옅은 회색, fg 거의 검정, muted 회색, line은 검정 저투명도, accent는 **세이지 그린**(#7E9A86 근처), Sage 전용 `--color-sage-orb` 파랑(#4F5BFF→#8EA2FF 그라데이션). success/warning/danger는 밝은 배경 대비 4.5:1 이상으로 재조정.
- `color-scheme: light`, `<meta name="color-scheme">`도 light로.
- 카드 radius 12→16px, 카드 그림자 추가, 주요 버튼(영상 불러오기 등)은 검은 알약 스타일.
- 하드코딩된 다크 색(`bg-white/5`, `text-white` 등)을 토큰으로 정리 — 토큰을 안 쓰는 곳을 grep으로 찾아 전부 교체.
- 다크 테마 토글은 만들지 않는다(사용자가 밝은 색감만 요청, YAGNI).

### B-2. 레이아웃
- **기존 3단 작업 흐름·헤더 기능·모달은 그대로** 유지한다. 겉모습만 바꾸고 동작/데이터 흐름은 바꾸지 않는다. 기존 단위 99·E2E 9 테스트가 계속 통과해야 한다.
- 원본의 세로 사이드바는 도입하지 않는다(CONTEXT는 한 화면 작업대라 이동할 페이지가 없음). 헤더 오른쪽 아이콘 버튼들을 원형 버튼 + 호버 툴팁으로 바꿔 같은 느낌을 낸다. **사용자 확정 2026-10-21.**

### B-3. 움직임
- 첫 진입·패널 내용 교체 시 `blur(8px)+opacity 0 → 선명` 등장, 카드 간 40~60ms stagger. CSS 키프레임으로 구현(새 의존성 없음; 원본은 Framer Motion이지만 CONTEXT는 미사용이므로 추가하지 않음).
- 카드 호버 시 `translateY(-2px)` + 그림자 강화.
- `prefers-reduced-motion`이면 전부 끔(기존 규칙 확장).

### B-4. Sage 구슬 (UI)
- `components/sage/` 신규: `SageOrb`(그라데이션 구 + 흰 눈 2개, 숨쉬기 스케일·글로우, 3~6초 랜덤 눈 깜빡임, 마우스 쪽으로 눈동자 약간 이동), `SageLauncher`(오른쪽 아래 검은 알약 "Sage에게 묻기"), `SagePanel`(오른쪽 슬라이드 패널, 폭 ~380px, 열리면 본문 영역이 줄어듦), 말풍선.
- 첫 진입 시 구슬이 중앙에 떠서 "안녕하세요, 콘솔 비서 Sage예요" 말풍선 1회 → 런처 위치로 이동. 1회 여부는 localStorage(비밀 아닌 UI 플래그만, try/catch로 실패해도 동작. 보안 정책은 CSRF 토큰만 금지).
- 헤더 검색창 "검색하거나 Sage에게 묻기…": 입력 후 Enter → Sage 패널 열고 그 질문을 보낸다.
- 추천 질문 칩 3개(예: "오늘 게시 몇 개 남았어?", "지금 선택한 영상 요약해 줘", "승인 대기 중인 댓글 있어?").
- 생각 중에는 구슬이 빠르게 맥동, 답변 텍스트는 받은 뒤 한 번에 표시(스트리밍은 비목표).

### B-5. Sage 답변 (서버)
- 신규 라우트 `POST /api/sage/ask` `{ question: string(1..500), selectedVideoId?: string }` → 성공 `{ answer }`, 실패 `{ error: { code, message } }` (기존 `app.ts` 라우트와 같은 형식, 봉투 없음). zod로 검증, 기존 CSRF·localGuard 적용.
- 호출 경로: 예산 예약·`ai_usage` 기록이 빠지지 않도록 `orchestrator/llmRunner.ts`의 `runAgentCall`을 거친다(설계자 결정). 단 작업 큐(QUEUED→RUNNING)에는 넣지 않고 동기 호출, Sage 전용 타임아웃 60초, 동시 요청은 1건만(진행 중이면 409 `SAGE_BUSY`).
- Mock Provider일 때는 LLM을 부르지 않고 라우트에서 상황 요약 기반 템플릿으로 답한다(mockLlm 수정 없음).
- 주입 방지: 질문과 상황 요약을 `agents/prompts.ts`의 `untrusted()` + `INJECTION_GUARD` 패턴으로 감싼다.
- 서버가 **읽기 전용 상황 요약**을 만들어 프롬프트에 넣는다: 오늘 게시 수/한도, 작업 큐 상태, Provider 상태, 선택 영상의 제목·분석 요약·댓글 후보 상태, 최근 실행 이력 몇 건. 이 값들은 기존 서비스/DB 조회 함수를 재사용.
- LLM 호출은 기존 `clients/llm.ts` 추상화 + 기본 Provider(`claude -p`, 구독) 사용 — 종량 API 호출 없음(비용 0원 원칙). Mock Provider에서는 상황 요약 기반 템플릿 답변.
- Sage는 **답만 한다**. 게시·승인·설정 변경 같은 행동은 하지 않는다(안티골: Sage가 댓글을 대신 게시하는 것).
- 시스템 프롬프트: 한국어, 3~5문장, 모르는 건 모른다고, 상황 요약에 없는 수치는 지어내지 않기. 질문 텍스트는 사용자 입력으로 감싸 프롬프트 주입 방지 규칙 적용(기존 `security/` 패턴 따름).
- 실패 시(타임아웃·Provider 없음) 패널에 친절한 오류 문구 + 다시 시도.

### B-6. 검수
- 파트 A 스킬의 대조 단계로 원본 장면(1.3s / 2.3s / 4.2s / 6.0s)과 CONTEXT 스크린샷을 나란히 비교한 표를 남긴다.
- 테스트: Sage 라우트 단위 테스트(검증 실패, Mock 답변, 상황 요약 포함 여부), 컴포넌트 동작 E2E 1~2개(런처 → 패널 열림 → 질문 → 답변 표시). 기존 테스트 전부 통과.
- 접근성: 구슬은 `aria-hidden`, 런처·패널은 버튼/대화상자 역할과 포커스 관리, Esc로 닫기, 대비 4.5:1.
